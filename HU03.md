# HU03 — Checagem rápida e factual no player

Issue: #3 (Refs #3). Épico E1 — Gatilho e Ativação. Feature F2.1 — Disparo e Exibição Acessível WCAG. Requisitos RF-01, RF-09, RNF-01, RNF-02 e RNF-07. ADR-001: isolamento; ADR-002: proxy sem chaves na extensão; ADR-003: cache local de 24h.

## Entrega e critérios de aceitação

| Critério | Implementação | Evidência automatizada |
|---|---|---|
| Confirmação visual em até 1s | Texto e status acessível no clique; painel com estado de processamento | Playwright mede o próximo frame após o feedback |
| Síntese útil em até 10s | Cache → leitura do player → legendas → proxy → renderização. Prazo total de 9,5s desde o clique, incluindo leitura HTTP; falha encerra o carregamento e permite repetir | Playwright mede clique até o frame da síntese; backend real em modo demo, HTTP local, conteúdo YouTube controlado |
| Vídeo recente recuperado localmente sem nova requisição | `chrome.storage.local` antes de acessar legendas; TTL de 24h com expiração inclusiva; dados inválidos são descartados | Playwright bloqueia fetch do worker no cache hit, verifica uma única extração de legendas e exige renderização <100ms |

As três verificações passam no ambiente controlado. A segunda ainda depende da integração com a IA própria, ainda em preparação, para homologação factual em produção. Conforme orientação do responsável, essa integração fica pendente nesta entrega. Timeout é tratamento de falha, não resultado útil.

## Fluxo e robustez

- Um iframe pré-carregado avisa quando está pronto e recebe o estado mais recente. Mensagens conferem origem e janela remetente.
- O worker usa `chrome.scripting.executeScript` no mundo MAIN para ler somente as faixas de legenda do vídeo atual. A extração não depende de globais inacessíveis ao content script isolado. As URLs aceitas são limitadas ao endpoint HTTPS de legendas do YouTube; XML e JSON3 são suportados.
- A permissão `scripting` permite essa leitura no host já autorizado. A extensão inicia também na home para acompanhar a navegação SPA até um vídeo; não analisa nem persiste histórico sem acionamento.
- Ausência de faixas, falha HTTP, transcrição vazia, backend indisponível e timeout têm tratamentos distintos. A extração usa AbortSignal. Respostas tardias não alteram outro vídeo ou uma tentativa posterior.
- O botão usa `aria-disabled` durante processamento para impedir duplicação sem perder foco. Enter/Espaço não chegam aos atalhos globais do player. Escape fecha o painel e restaura foco. Tab/Shift+Tab alcançam as fontes.
- O cache contém somente a resposta concluída, timestamp e TTL. Falhas de leitura/persistência não transformam sucesso factual em erro. Resultados sem o contrato atual, incluindo caches antigos sem identificação de demonstração, são descartados.
- `analysisMode` é obrigatório (`demo` ou `live`) nos contratos Python, TypeScript e JSON Schema. Atualizar backend e extensão juntos. O painel identifica resultados simulados; provedores não implementados retornam 503 em vez de análise fictícia. Health informa estado degradado e conectores não integrados.

## Testes reproduzíveis

Pré-requisitos: Node >=20, Python >=3.12. Use ambiente virtual no backend e instale as dependências antes dos comandos abaixo.

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/ruff check .
.venv/bin/python -m pytest --cov=app --cov-report=term-missing -W error

cd ../extension
npm ci
npm run typecheck
npm run test:coverage
npm run build
npx playwright install chromium
E2E_PYTHON=../backend/.venv/bin/python npm run test:e2e
```

A variável `E2E_PYTHON` é resolvida a partir de `backend/` pelo servidor de testes; também pode receber o caminho absoluto do Python escolhido. A porta 8000 deve estar livre. O Playwright inicia e encerra seu próprio backend com `LLM_PROVIDER=mock`, sem credenciais, e usa um perfil Chromium descartável.

Para coletar amostra de latência:

```bash
E2E_PYTHON=../backend/.venv/bin/python npm run test:e2e -- --grep feedback --repeat-each=10
```

A CI executa cobertura, build, Chromium e axe. Relatórios e traces de falhas são arquivados em `hu03-test-evidence`. O limiar de cobertura da extensão é 81% por arquivo em linhas, instruções, funções e ramificações; o backend exige pelo menos 81% no relatório com ramificações. Resultados medidos desta entrega: [evidências locais](docs/hu03-evidencias.md).

## Definition of Done e limites

- [x] Tipagem, build e Ruff sem erros.
- [x] Testes unitários e de integração passando.
- [x] Cobertura superior a 80% nos módulos alterados.
- [x] Nenhum segredo incluído nos arquivos alterados.
- [x] Tab, Shift+Tab, Enter, Espaço, Escape e restauração de foco testados no Chromium.
- [x] Zero violações axe WCAG 2.1 A/AA no painel e botão, nos estados exercitados; contraste das classificações testado.
- [x] SLA, cache e tarefas longas medidos no ambiente controlado.
- [x] Branch e commits seguem CONTRIBUTING.md.
- [ ] Integração de IA/busca real e avaliação da qualidade factual.
- [ ] Homologação de latência com rede e vídeos reais do YouTube após essa integração. A API interna de legendas do YouTube pode mudar ou limitar requisições; tais falhas são mostradas ao usuário.
- [ ] Revisão humana com leitor de tela e do restante da WCAG: axe não certifica conformidade integral.
- [ ] Publicação desta rastreabilidade no catálogo/matriz e build estrito do portal externo de documentação, que está em outro repositório.

RF-09/HU06 são dependências necessárias à HU03 apesar da classificação em outra onda. O limite <100ms da ADR-003 é verificado adicionalmente ao RF-09 (<1s). O teste usa prazo desde o clique, mais estrito que o Gherkin que parte da transcrição extraída. A amostra registra P90 (RNF-01), enquanto a suíte falha se qualquer execução superar o limite determinístico.
